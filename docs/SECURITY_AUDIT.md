# Security audit — Epsilon app and API

Date: 2026-11-23. Scope: this repo (Expo app) and `Epsilon-Back-End` (Fastify API), plus the
configuration of the demo server (read only). Branch `security/audit` in both repos.
Every finding was reproduced with a failing test before the fix. Enforcement is server-side;
the app is never trusted for money, ownership or eligibility.

Severity: High = abuse affects other users or money at scale; Medium = abuse needs effort or a
trusted party; Low = limited impact; Info = defence in depth or accepted design.

Back-end regression tests: `test/security.test.ts` (back-end repo) unless another file is named.

## Checked with no finding

- OTP: 6 digits, HMAC-stored, constant-time compare, 2-minute expiry, 5 attempts per code (counted outside the transaction), 60 s resend, 5 codes an hour per phone, single use.
- Sessions: refresh tokens stored as SHA-256, rotated on use, reuse revokes the family; logout and deletion revoke at once (every request checks the session family); deletion needs a sign-in within 10 minutes.
- Google sign-in: signature (JWKS), issuer, audience, RS256 only, verified e-mail; accounts are never linked by e-mail.
- Input: strict Zod schemas on every body, query and param; Drizzle parameterises SQL; `ILIKE` search escapes `%`, `_`, `\`.
- Errors: 4xx bodies never echo submitted values; 500s say `Internal error`; logs carry the route pattern, not URLs, bodies or the `Authorization` header.
- Limits: 16 KB bodies (24 MB only on receipt import, 20 MB at Caddy); images checked by magic bytes and dimensions, never written to disk; QR text up to 2048 chars, `https://monitoring.e-kassa.gov.az` only, never fetched.
- Config refuses in production: console or e-mail OTP, fixture receipts, debug dumps. Secrets are validated by length and never echoed.
- App: tokens in SecureStore; React Query cache cleared at sign-in, logout and session expiry; rating outbox keyed by user and cleared on logout; `allowBackup: false`; Sentry with `sendDefaultPii: false`; input lengths match the API limits; one import at a time in the e-kassa screen; release builds refuse non-HTTPS or non-production API URLs.
- Secrets: no `.env`, keystore, `credentials.json` or key file is tracked in either repo. Back-end `npm audit --omit=dev`: 0 vulnerabilities.
